# AI usage telemetry

`programs.aiUsage` acquires usage/quota numbers from AI providers and emits
a **bar-agnostic JSON document**. Bars do not talk to providers; they translate
that document into their own protocol through a small adapter.

This split exists because the original implementation fused four concerns into
one `writeShellApplication` living inside a bar module: HTTP, credentials,
thresholds, text layout, and the bar's `{icon, state, text}` wire format. Adding
a provider meant editing a bar module, and adding a bar meant duplicating the
acquisition logic.

## Architecture

```
                    programs.aiUsage              (policy + acquisition)
                            |
                     lib/default.nix              pure: providers -> config JSON
                            |
                 ai-usage-config.json             version 1, in the Nix store
                            |
        module/package.nix -> ai-usage            fetch, cache, orchestrate
                            |
                  module/ai-usage.jq              pure: body -> document
                            |
                bar-agnostic document             version 1, on stdout
                            |
        +-------------------+-------------------+
        |                                        |
  a bar adapter                        (waybar, polybar, ...)
        |                                          not implemented
  bar-native wire format
```

Four artefacts with deliberately different purity levels:

| Artefact | May read | Why |
| --- | --- | --- |
| `lib/default.nix` | `lib` only | pure data transformation, unit-testable without a host |
| `module/ai-usage.jq` | its four jq arguments | pure function; every semantic rule is testable against a fixture |
| `module/package.nix` | its `callPackage` arguments | ordinary derivation; config arrives as a *file path*, so the package never sees `config` |
| `module/default.nix` | `config.*` | the only file allowed to; it wires the three above together |

That layering is what keeps everything except `module/default.nix` consumable
outside Home Manager, and it is why this repository can be tested without a host
configuration at all. The rule is a hard one: none of the first three may mention
`config`, `osConfig` or `home-manager`.

Bar translation is deliberately **out of scope** here. A consumer converts the
document to its bar's wire format in its own adapter; this repository ships no
adapter and knows nothing about any bar.

## Config schema (version 1)

Generated by `lib/`, written to the store by the Home Manager
module, and read by `ai-usage`. Disabled providers are **absent**, not present
with `enable = false`, so querying one is a usage error rather than a silent empty
result.

```json
{
  "version": 1,
  "providers": {
    "<name>": {
      "name": "<name>",
      "enable": true,
      "timeout": 3,
      "refreshInterval": 300,
      "retryInterval": 60,
      "maxStaleAge": 900,
      "source": { "http": { "url": "...", "headers": { "...": "..." } } },
      "credential": { "secretTool": { "service": "...", "account": "..." } },
      "metrics": { "<metric>": { "from": {...}, "unit": "...", "required": true, "nullText": "..." } },
      "rules": [ { "metric": "<metric>", "warnAt": 80, "criticalAt": 90 } ],
      "format": "{metric}",
      "tooltipFormat": "{metric}"
    }
  }
}
```

`source`, `credential` and `metrics.<name>.from` are **tagged unions**
(`lib.types.attrTag`), so `{path = ...; expression = ...;}` is unrepresentable
rather than merely undefined. `credential` and `tooltipFormat` are omitted
entirely when null; `nullText` likewise; `required` is omitted for `percentOf`
metrics, which are never required.

Attribute keys are emitted lexicographically by `builtins.toJSON`, which is what
fixes the rendering order of `metrics` in the document.

### `source`

| Tag | Fields | Behaviour |
| --- | --- | --- |
| `http` | `url`, `headers` (attrs of string) | `curl --silent --show-error --fail --max-time <timeout>`. The literal token `{credential}` in any header value is replaced at runtime, so the secret never enters the Nix store. |
| `command` | shell string | stdout is the response body. For providers that expose no usage endpoint at all. |

### `credential`

| Tag | Fields | Behaviour |
| --- | --- | --- |
| `file` | `path`, `jqPath` (default `.`) | reads a JSON file, selects with jq |
| `secretTool` | `service`, `account` | `secret-tool lookup service <s> account <a>` |
| `command` | shell string | stdout is the credential |

An unreadable file, a locked keyring, or an empty result is a *fetch* failure: an
actionable line goes to stderr and the document degrades, but the exit code stays
`0`.

### `metrics.<name>.from`

| Tag | Fields | Pass |
| --- | --- | --- |
| `path` | list of strings | 1 |
| `timestamp` | `path`, an ISO-8601 UTC instant | 1 |
| `expression` | jq filter over the raw body | 1 (pre-evaluated by the orchestrator) |
| `percentOf` | `of`, `total` | 2 |

The tags are mutually exclusive by *type*: `metrics.<name>.from` is a
`types.attrTag`, so `{path = ...; timestamp = ...;}` fails to evaluate rather
than resolving by some undocumented precedence.

`expression` is evaluated by `ai-usage`, not by the core, and handed in as a
pre-computed value. The core therefore stays a pure function of its arguments,
and a malformed filter cannot corrupt the document.

`timestamp` yields **epoch seconds**, and should be paired with `unit = "raw"`:
percent clamping and dollar flooring would both corrupt an instant. Emitting a
number rather than a formatted string keeps time formatting out of this
repository — a consumer that wants "resets in 42m" has everything it needs, and
one that wants an absolute clock time can have that too.

The accepted syntax is exactly `%Y-%m-%dT%H:%M:%SZ`, after fractional seconds
and a `+00:00`/`-00:00` offset are normalised away. Anything else parses to
`null`, including a **non-UTC numeric offset**: `2026-08-21T23:10:00-05:00`
yields `null`, not a shifted epoch. Reinterpreting someone else's wall clock as
an instant produces a plausible-looking wrong answer, which in a status bar is
worse than a visible gap. The parse is total for every input — string, number,
container or absent — and `checks/laws` states that as `timestamp-total`.

### `metrics.<name>.unit`

| Unit | Normalisation | Rendering |
| --- | --- | --- |
| `percent` | clamp to `0..100`, then floor | bare number |
| `dollars` | clamp at `0`, then floor | `$` prefix |
| `raw` | none | bare value |

### `rules`

The document's severity is the **highest** severity any rule yields. No rules
means always `ok`. The alarm *direction* is inferred from the ordering of the
thresholds:

- `warnAt < criticalAt` — alarm on high values (`>=`, inclusive)
- `warnAt > criticalAt` — alarm on low values (`<=`, inclusive)

`warnAt == criticalAt` leaves the direction undefined and is rejected by a module
assertion.

## Document schema (version 1)

`ai-usage <provider>` prints exactly one JSON object on stdout and always
exits `0` — bars typically treat a non-zero exit or unparsable output as a hard
block error, so a failed read must still be a valid document.

```json
{
  "version": 1,
  "provider": "openrouter",
  "severity": "ok",
  "text": "$7/$20",
  "tooltip": "used $7 of $20 · $12 left",
  "percentage": 37,
  "metrics": { "limit": 20, "percent": 37, "remaining": 12, "usage": 7 },
  "stale": false,
  "age": 0,
  "error": null
}
```

| Field | Type | Meaning |
| --- | --- | --- |
| `severity` | `ok` / `warn` / `critical` / `unknown` | worst rule outcome, or `unknown` |
| `text` | string | `format` rendered; `?` when `unknown` |
| `tooltip` | string | `tooltipFormat` rendered, falling back to `format` |
| `percentage` | number or null | max over `percent`-unit metrics named by a rule |
| `metrics` | object | normalised values, lexicographic; `{}` when `unknown` |
| `stale` | bool | serving a cached body after a failed fetch |
| `age` | number or null | seconds since the last good response |
| `error` | string or null | non-null iff `severity == "unknown"` or `stale` |

Invariants, asserted by `checks/core` at named points and by `checks/laws` over a
generated domain:

- `severity == "unknown"` **if and only if** the body is unparsable or some
  required metric resolved to null, and `unknown` implies `text == "?"`,
  `metrics == {}`, `percentage == null` and `error != null`.
- `text` and `tooltip` never contain `<`, `>` or `&`. Bars that render pango
  markup commonly do not escape it (i3status-rust's `pango-str` formatter, for
  one, does not), so those characters would reach pango raw and corrupt the block.
  Stripping happens in the core's `show`, applied to every rendered value —
  including `nullText`, which is user-supplied and therefore untrusted. This is
  deliberately *not* a module assertion: the core must be safe for any config,
  including hand-written ones and the standalone use of `ai-usage.jq`, and
  validation at the module layer would not protect those.
- `text` and `tooltip` contain no residual `{token}`.
- Identical inputs produce byte-identical output. The core reads no clock.

A missing **required** metric makes the whole document `unknown`. That is
deliberate: a mistyped path should fail loudly rather than render empty text that
looks like a healthy zero.

## Cache schema (version 1)

`$XDG_CACHE_HOME/ai-usage/<provider>.json`, written atomically via
`<provider>.json.tmp` + `mv`, serialised across processes by
`flock` on `<provider>.lock`.

```json
{
  "version": 1,
  "fetchedAt": 1755000000,
  "ok": true,
  "error": null,
  "body": "<raw provider response>",
  "lastGoodAt": 1755000000
}
```

The cache stores the **raw body**, not the rendered document, so changing a
`format` string or a threshold re-renders from cache without a network call.

Refresh policy:

| State | Refetch when |
| --- | --- |
| last fetch succeeded | `now - fetchedAt >= refreshInterval` |
| last fetch failed | `now - fetchedAt >= retryInterval` |
| `--refresh` given | always |

After a failed fetch the last good body is still served, with `stale = true` and
`age` set, until `age > maxStaleAge`; then the document degrades to `unknown`. A
`flock` timeout is not a failure — the caller falls through to the cached value.

This is why the bar's poll interval is decoupled from the network: a 300 s bar
tick against a 300 s `refreshInterval` costs one cache read most of the time, and
lowering the bar interval costs nothing but cache reads.

## CLI

```
ai-usage <provider> [--refresh] [--config <path>]
```

| Exit | Meaning |
| --- | --- |
| `0` | a document was printed (possibly `unknown`) |
| `1` | the config file is missing or is not version 1 |
| `2` | usage error: no provider, unknown provider, disabled provider, extra argument, unknown flag |

`AI_USAGE_CONFIG` overrides the built-in config path; `--config` overrides both.
Both exist for testing and for running the tool against a scratch config without
a rebuild.

`--refresh` is the only way to force a network call. It is deliberately **not**
bound to a bar click: in i3status-rust, for instance, an explicit click handler
*replaces* the default left-button behaviour, which is format cycling.

## Semantics

Let `D` be the parsed body (`null` if unparsable), `M` the metric set, `R` the
rules.

Pass 1 — direct extraction, un-normalised:

```
v1(m) = D[path(m)]           if from(m) = path
      = epoch(D[path(m)])    if from(m) = timestamp
      = expressions[m]       if from(m) = expression
      = undefined            if from(m) = percentOf
```

`epoch` is total: `epoch(x) = null` for every `x` that is not an ISO-8601 UTC
instant, including a non-UTC numeric offset.

Pass 2 — derived:

```
v2(m) = null                             if v1(of) = null or v1(total) = null or v1(total) <= 0
      = v1(of) * 100 / v1(total)         otherwise
```

Pass 3 — normalisation, applied last so that thresholds and percentages are
computed from the *unrounded* values:

```
v(m) = norm(unit(m), v1(m) or v2(m))
```

Severity:

```
sev(m, r) = unknown   if v(m) = null
          = critical  if (warnAt < criticalAt and v(m) >= criticalAt) or (warnAt > criticalAt and v(m) <= criticalAt)
          = warn      if (warnAt < criticalAt and v(m) >= warnAt)     or (warnAt > criticalAt and v(m) <= warnAt)
          = ok        otherwise

severity  = unknown   if D = null, or any required m has v(m) = null
          = max(sev(m, r) for r in R)   under ok < warn < critical < unknown
```

Multiplying before dividing (`of * 100 / total`) preserves precision for small
dollar amounts. Flooring after clamping means a value of `79.9` is `79` — below a
`warnAt` of `80` — and that `19.6` dollars against a `20` limit renders `$19/$20`
rather than a rounded `$20/$20` that would falsely read as exhausted.

## Module option reference

`programs.aiUsage`:

| Option | Type | Default | Notes |
| --- | --- | --- | --- |
| `enable` | bool | `false` | installs the `ai-usage` binary into `home.packages` |
| `providers` | attrs of provider | the built-in `claude` and `openrouter` | the registry below |
| `package` | package | built from this configuration | read-only; depend on this rather than on a name |
| `configFile` | path | generated | read-only; the store path passed to the binary |
| `settings` | attrs | derived from `providers` | read-only; see below |

### `settings`

`settings` is the rendered schema-version-1 config document — exactly the value
serialised into `configFile`. It exists so a consumer can assert on *what this
module produced* rather than re-deriving it:

```nix
config.home-manager.users.alice.programs.aiUsage.settings.providers.claude.credential.file.path
```

The alternatives are worse. Importing this repository's `lib` from a consumer's
test widens the public API for a test convenience and duplicates the derivation;
reading `configFile` back with `fromJSON (readFile ...)` is import-from-derivation
inside `nix flake check`. Because `settings` is the single call site of
`mkConfig`, observing it cannot disagree with what was written to disk.

It is typed `attrs`, deliberately: the document's shape is pinned by
`checks/config`'s golden diff, and a second schema encoding as a `submodule`
would be a duplicate owner of the same invariant.

### `providers.<name>`

| Option | Type | Default | Notes |
| --- | --- | --- | --- |
| `enable` | bool | `true` | disabled providers are dropped from the generated config |
| `timeout` | positive int | `3` | per-request `curl` timeout; a dead endpoint cannot stall the bar |
| `refreshInterval` | positive int | `300` | minimum seconds between successful fetches |
| `retryInterval` | positive int | `60` | minimum seconds between retries after a failure |
| `maxStaleAge` | positive int | `3 * refreshInterval` | how long the last good body may still be served |
| `source` | tagged union | required | `http` or `command` |
| `credential` | tagged union or null | `null` | `file`, `secretTool` or `command` |
| `metrics` | attrs of metric | required | metric names are the template tokens |
| `rules` | list of rule | `[]` | `{metric, warnAt, criticalAt}` |
| `format` | string | required | `{metric}` tokens |
| `tooltipFormat` | string or null | `null` | falls back to `format` |

Module assertions (each named in its message, each with a violating
configuration in `checks/module`):

1. every `rules[].metric` names an existing metric
2. `warnAt != criticalAt`
3. `percentOf` operands exist and are not themselves `percentOf` — this is what
   makes the two-pass resolution terminating
4. metric names match `[a-zA-Z][a-zA-Z0-9]*` (they are interpolated into a jq
   regex and used as template tokens)
5. `format` and `tooltipFormat` contain no `<`, `>` or `&`
6. every `{token}` in a template names an existing metric
7. at least one provider is enabled when the feature is on
8. `maxStaleAge >= refreshInterval`
9. a header substituting `{credential}` has a credential source configured

## Worked example — an HTTP provider with a keyring credential

```nix
programs.aiUsage.providers.openrouter = {
  source.http = {
    url = "https://openrouter.ai/api/v1/key";
    headers.Authorization = "Bearer {credential}";
  };
  credential.secretTool = {
    service = "openrouter_usage";
    account = "status_bar";
  };
  metrics = {
    usage = { from.path = ["data" "usage"]; unit = "dollars"; };
    limit = { from.path = ["data" "limit"]; unit = "dollars"; required = false; nullText = "∞"; };
    remaining = { from.path = ["data" "limit_remaining"]; unit = "dollars"; required = false; nullText = "∞"; };
    windowUsage = {
      from.expression = ''
        if (.data.limit == null) or (.data.limit_remaining == null)
        then null else .data.limit - .data.limit_remaining end
      '';
      unit = "dollars"; required = false; nullText = "∞";
    };
    percent = { from.percentOf = { of = "windowUsage"; total = "limit"; }; unit = "percent"; };
  };
  rules = [ { metric = "percent"; warnAt = 80; criticalAt = 90; } ];
  format = "{usage}/{limit}";
  tooltipFormat = "used {usage} of {limit} · {remaining} left";
};
```

An unlimited key (`limit == null`) renders `$7/∞`; `percent` is null, so no rule
fires and the severity is `ok`. A zero or absent `limit` likewise yields no
percentage rather than a bogus 100 %.

Note which quantity the ratio is taken over. OpenRouter's `usage` is lifetime
spend, while `limit` applies to the period named by `limit_reset`, so
`percentOf(usage, limit)` compares two different windows and reports a long-lived
account as permanently over budget. `limit_remaining` is already window-scoped
server-side, so `limit - limit_remaining` is spend against the active window
whatever the reset period is, and needs no knowledge of the `limit_reset` enum.
`usage` is kept as informational lifetime spend; only the denominator's partner
moved. This is legal under assertion 3 because both `percentOf` operands are
pass-1 metrics — `windowUsage` by expression, `limit` by path.

When the server reports a `limit` but no `limit_remaining`, `windowUsage` and
hence `percent` are null: no severity signal rather than a plausible wrong one,
the same judgement as the non-UTC timestamp rule above.

## Worked example — a command provider

For a service with no usage endpoint, produce the body locally:

```nix
programs.aiUsage.providers.local = {
  source.command = "cat ~/.local/state/spend.json";
  metrics = {
    spent = { from.expression = "[.entries[].cost] | add"; unit = "dollars"; };
    budget = { from.path = ["budget"]; unit = "dollars"; };
    percent = { from.percentOf = { of = "spent"; total = "budget"; }; unit = "percent"; };
  };
  rules = [ { metric = "percent"; warnAt = 80; criticalAt = 95; } ];
  format = "{spent}/{budget}";
};
```

Note the descending-threshold form for a "credit remaining" style provider:
`{metric = "remaining"; warnAt = 5; criticalAt = 1;}` alarms as the value *falls*.

## Checks

`nix flake check --keep-going` runs five layers, each with exactly one owner:

| Check | Layer | Pins |
| --- | --- | --- |
| `core` | pure core semantics | 41 rows over `module/ai-usage.jq`: every semantic rule, thresholds, clamping, flooring, staleness, `percentage`, metric order, pango safety, timestamp parsing, window-scoped ratios |
| `laws` | universally quantified properties of the core | 552 generated instances over a bounded adversarial domain: document totality, pango safety, normalisation, the severity lattice, timestamp totality, determinism |
| `config` | pure config builder | golden `expected.json` for the shipped defaults, plus provider filtering, `percentOf` key omission, null stripping, and drift between the golden and the core's fixtures |
| `runtime` | orchestrator | 20 groups with stub `curl`/`secret-tool`: cold fetch, warm cache with no network, `--refresh`, interval expiry, stale serving, retry throttling, stale expiry, recovery, all three credential kinds, command source, exit codes, atomic writes, concurrency |
| `module` | Home Manager module | option shape, `settings` contents, package installation, and a violating configuration for each of the nine assertions |

The golden file `checks/config/expected.json` is the single place the shipped
defaults are pinned. **Consumers must not re-pin them.** A downstream test may
assert on composition — that a user enabled the module, that `settings` has the
providers it expects, that the credential path tracks `home.homeDirectory` — but
endpoints, thresholds, format strings and units have exactly one owner, here.

`checks/core` pre-evaluates `from.expression` filters itself, mirroring the loop
in `module/package.nix` with the same error handling, because jq has no `eval` and
the core receives expression *values* rather than filters. The duplication is
deliberate: a shipped filter is only genuinely covered if some check *executes*
it, and no other layer does. `checks/config` pins a filter as text only, and
`checks/runtime` drives its own hand-written config by design. A row may still
declare `expressions` explicitly, which is applied as an override on top of the
resolved values, for a value the orchestrator can produce but a filter cannot.

`checks/module` evaluates the module with `lib.evalModules` against a ~20-line
stub of the three Home Manager options it touches (`home.homeDirectory`,
`home.packages`, `assertions`) rather than taking a `home-manager` input. That
keeps this repository at a single input and keeps evaluation fast.

The cost is **stub drift**: if Home Manager changes the type of one of those
options, this check will not notice. That is acceptable because consumers
evaluate the module inside a real `home-manager` configuration, so drift surfaces
downstream at build time rather than silently.

Assertions are testable in both directions here because in the module system they
are *data* — a list of `{assertion, message}` that a host evaluator forces later —
not exceptions. Forcing the messages only proves they evaluate; `checks/module`
proves each one actually fires.

### Laws

`checks/laws` **supplements** `checks/core`, it does not replace it. An example
row pins *intent* at a named point — `percentOf(16, 20) == 80`, and why — and is
readable documentation. A law pins *structure* over a whole domain:
`norm . norm = norm`, or "adding a rule can only raise severity". A green law
suite with no examples is unreadable to the next maintainer, so no example row is
ever deleted because a law subsumes it.

The suite is generated in Nix — `lib.cartesianProduct` over small,
boundary-dense domains — and verified in jq. There is no property-testing
framework and no randomness: the same instances run on every build, so a failure
is always reproducible from the reported instance. The verifier returns *every*
violation rather than the first, because a harness that reports one
counterexample is a worse debugger than an example suite.

Laws needing two runs of the core — determinism, rule-order permutation,
rule-set inclusion, value monotonicity, normalisation idempotence — are
expressed as *paired* instances sharing a `pairId`, which the verifier groups.
This is what lets `f(f(x)) = f(x)` be stated without splitting the core into a
jq module and testing something other than the artefact that ships. The core is
driven exactly as `module/package.nix` drives it, through `--argjson provider`,
`--rawfile body`, `--argjson expressions` and `--argjson meta`.

Two laws are load-bearing beyond their own statement. **Determinism** —
identical inputs yield byte-identical stdout — mechanically enforces the purity
row of the table above; it is the permanent guard against reintroducing `now`
into the core. **`unknown` if and only if the body is unparsable or a required
metric is null** closes the reverse direction that `checks/core` leaves open,
which is what catches a new optional metric accidentally degrading a whole
provider.

Since jq has no typechecker, the totality laws *are* the type system: the core's
contract is `(provider, body, expressions, meta) -> Document`, total, and only a
law can state that.

The ceiling is worth stating plainly: exhaustive laws over a small adversarial
domain are **bounded verification, not proof**. jq is not verifiable. The
escalation path is the typed-core port listed under extension points, at which
point `proptest` and `kani` bounded model checking apply — and this fixture and
law suite transfers unchanged.

## Manual validation

```sh
ai-usage claude | jq .
ai-usage openrouter | jq .

ls -l "${XDG_CACHE_HOME:-$HOME/.cache}/ai-usage/"   # two .json files, no .tmp
```

- Run a provider twice inside `refreshInterval`: the second call must not touch
  the network (watch `fetchedAt` in the cache file stay put).
- Lock the keyring, then `ai-usage openrouter --refresh`: the last good text is
  still served with `"stale": true`, and degrades to `?` only after
  `maxStaleAge`.
- On a host where the module is disabled, `ai-usage` must not be on `PATH`.

Two runtime dependencies are not enforced by Nix and will degrade the
corresponding provider: a logged-in Claude Code session at
`~/.claude/.credentials.json`, and an OpenRouter key in the keyring
(`secret-tool store --label='OpenRouter' service openrouter_usage account
status_bar`).

The Anthropic utilisation endpoint is **undocumented** and may change or
disappear without notice. When it does the Claude block degrades to `?` and
`Warning` instead of breaking the bar, and
`providers.claude.source.http.url` is the override point.

## Planned extension points

Everything below is deliberately **not** implemented. The schema was shaped so
that each is additive.

**OpenAI.** The Costs/Usage API requires an *admin* key, not a project key, so it
needs a separate credential from the one the CLI uses. `start_time` is Unix
seconds and `bucket_width` should be `1d`; results are paginated via `next_page`
and arrive as an array of buckets, so a total needs array aggregation
(`from.expression`) rather than a path. There is no spend *limit* in the
response — a budget has to be supplied by the user. Blocked on pagination and a
`literal` metric kind.

**opencode.** Exposes no usage endpoint. The TUI serves per-message cost only, on
a randomly chosen port, so a `source.command` would have to discover the port and
walk `/session/:id/message` summing costs. Possible today via `source.command`,
but fragile enough not to ship.

**opencode Zen.** No public balance API at all.

**A `query` value union.** `{literal | epoch | command}` for request-time
parameters — needed for OpenAI's `start_time`, which must be "now minus 30 days"
at fetch time rather than at build time.

**A `literal` metric kind.** For user-supplied constants such as a monthly
budget, so `percentOf` has a denominator when the provider does not give one.

**Pagination.** A `source.http.pagination` field following a cursor field until
exhausted, concatenating bodies into an array.

**A systemd warm-cache timer.** Would remove the first-render latency after
login. Not needed while the bar tick and `refreshInterval` are both 300 s.

**Waybar / polybar adapters.** The document already carries `tooltip`,
`percentage` and `stale`, which is more than either bar needs; only the wire
format differs. Waybar wants `{text, tooltip, class, percentage}`.

**A Rust port of the core.** The jq core is ~120 lines and fully covered by
`checks/core`; a port would be a performance decision, not a correctness one,
and the fixture suite transfers unchanged.
